# V6 RC.7 — Expo SQLite atomic batches

## Changes

- Expo SQLite implements optional `BatchEventStoreAdapter`: `appendBatch` and
  snapshot-consistent `getStreamVersions`, reusing the existing shared types.
- Every written stream needs exactly one expected version. Additional read-only
  dependencies are checked in the same transaction, including empty streams.
- Acquire SQLite's writer reservation before reading any versions. Preserve input
  event order and assign contiguous stream sequences independently. Remove the
  ambiguous `domain::identifier` grouping key.
- Typed batch validation, stream conflicts and duplicate-event errors; insertion
  failures roll back the entire batch. Existing append/single-stream APIs use the
  same write path. Persisted bodies, sequences and schema are not rewritten.
- Correct the global-log documentation: allocation order is not PostgreSQL commit
  order. Explain stopped-writer rebuild/export, bounded decision dependencies,
  consumer retry/receipt ownership, and platform-specific transaction limits.
- CI uses Node 22 for the real SQLite engine test bridge.

## Compatibility and scope

Core/aggregate do not require the optional capability. PG transaction composition
and vector pagination are unchanged; no global PG lock is introduced. Other adapters
are not extended. All six public packages receive the same prerelease version.

SQLite retains its native single-writer concurrency ceiling. Competing connections
can report database-locked/busy errors: retry after rollback with bounded backoff.
On stream conflicts, reload state and re-decide. No receipt transaction composition
API is exposed for SQLite; use PG's existing scope for events plus consumer SQL.
No consumer business models or changes to core-services are included.

## Local verification

- `PGPORT=55432 yarn test --stream`: **16 suites, 253 tests passed**, no skipped tests.
- PG: **91 tests**, real PostgreSQL 15 Docker service, including independent adapter
  connections, transaction/receipt rollback and interleaved-commit pagination.
- SQLite: **23 tests**: 11 existing compatibility mocks and 12 real SQLite engine
  cases, including independent worker connections with reversed stream order for
  both empty and existing streams, insertion rollback and read-only dependencies.
- Core/aggregate/revert/example: **139 tests**, including snapshot and import/export
  regressions. Types package has no separate test suite.
- `yarn lerna run compile`: all **7 packages** built successfully.

SQLite tests bridge Expo's API shape onto Node's built-in SQLite engine. Actual
Expo iOS/Android connection creation is not verified; exclusive transactions do not
support web. Custom PG RLS, replicas, CDC and unbounded vector populations remain
outside the tested boundary. Online rebuild/reset coordination remains consumer-owned.
